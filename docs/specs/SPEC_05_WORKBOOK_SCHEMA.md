# SPEC_05 — Workbook schema (binding)
One `.xlsx`, **exactly two sheets**, generated by `tools/sqe_workbook.py` from CSV + gtest XML. No scope/gap/defect/traceability sheets.

## 1. Sheet 1 "Test Inventory" — one row per student-authored test (incl. characterization tests and probes)
| # | Column | Content rule |
|---|---|---|
| 1 | Test ID | `SQE-…` (SPEC_01 §3), unique |
| 2 | Component / Function | e.g. `DataValidatorGroup::get_best` |
| 3 | Purpose / Scenario | one sentence; say "characterization (F-nn)" or "probe (F-nn)" where applicable |
| 4 | Key Controlled Input / State | the inputs/state that matter (params, messages, prior calls, time) — compact |
| 5 | Expected Result | the oracle, with its source in brackets, e.g. `idx=1; failover_count=1 [code L187–L226]` |
| 6 | Execution Result | **filled from XML**: PASS / FAIL / BLOCKED / NOT EXECUTED (+ short note for non-PASS) |
| 7 | Structural Coverage Target | decision IDs and outcomes, e.g. `DVG-D13 T (C,D); DVG-D15 F (L)` |
| 8 | Test File / Evidence Reference | `SqeDataValidatorGroupTest.cpp::SqeDvgMcdcTest.MC04_… ; evidence/tests/xml/unit-SqeDataValidatorGroup.xml` |
CSV source: `work/inventory/test_inventory.csv` with header
`test_id,component,purpose,controlled_input,expected,coverage_target,test_ref,gtest_name,manual_status,manual_note`
(`gtest_name` = `Suite.Test` used to join XML results; `manual_status` only for BLOCKED/NOT EXECUTED tests that have no XML).

## 2. Sheet 2 "MC-DC Evidence" — one row per target evaluation (sheet names cannot contain "/")
| # | Column | Content rule |
|---|---|---|
| 1 | Decision ID | `DVG-D13` … |
| 2 | Source | `DataValidatorGroup.cpp:187-190` |
| 3 | Decision | verbatim expression (first row of a decision block; may repeat) |
| 4 | Conditions | legend, e.g. `A=max_conf<0.9; B=conf>=0.9; …` |
| 5 | Test ID | `SQE-DVG-MC-04` |
| 6 | Evaluation | e.g. `call 2, i=1` |
| 7–13 | C1 … C7 | `T`, `F`, `NE(T)`, `NE(F)`; empty if the decision has fewer conditions |
| 14 | Outcome | `T` / `F` |
| 15 | Independence Pair | partner Test ID(s) for the condition(s) in col 16 |
| 16 | Condition Shown Independent | letter(s), e.g. `D` |
| 17 | MC/DC Form | `unique-cause` / `masking` / `—` (row only provides T/F evidence) |
| 18 | Observability | `O1` / `O2` / `O3` (+ evidence path for O3) |
| 19 | Notes | coupling, feasibility, float values, finding refs |
CSV source: `work/mcdc/mcdc_matrix.csv` with header
`decision_id,source,decision,conditions,test_id,evaluation,c1,c2,c3,c4,c5,c6,c7,outcome,pair_with,shows,form,observability,notes`

## 3. Validation (script fails on any violation)
≤ 2 sheets · unique Test IDs · every inventory row has an XML result or a manual status + note · every MC/DC `test_id` exists in the inventory ·
every `pair_with` refers to a row of the same decision · per decision: each condition appears T and F (logical value), outcome T and F, each condition
has ≥ 1 pair (checked by `tools/sqe_mcdc_check.py`) · no formulas (pure evidence; nothing to recalculate).

## 4. Formatting
Arial 10; bold white header on dark teal; frozen header row; autofilter; wrapped text; column widths set; conditional fills (PASS green, FAIL red,
BLOCKED amber; T light-green, F light-red, NE grey); header cell comments explain each column and the T/F/NE notation (acts as the legend without
adding a sheet).
