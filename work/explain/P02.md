## What `make tests` actually runs
Three kinds of tests all go through the same `ctest` invocation:
- **`unit-*`** — GTest binaries for pure logic with no runtime services (params/uORB/time not read at construction).
  This is the level our Area A (`DataValidator`) and Area B (`DataValidatorGroup`) tests will use.
- **`functional-*`** — GTest binaries that need `gtest_functional_main`, which boots a minimal uORB + parameter
  system before the test body runs. This is the level our Area C (`FailureDetector`) and D (`FailureInjector`) tests
  will use, since both read params at construction and subscribe to uORB topics.
- **`sitl-*`** — full SITL script tests that start actual PX4 modules against a simulated vehicle (e.g.
  `sitl-imu_filtering`, which runs for ~10 seconds). None of our scope needs this level — see `work/scope/SCOPE_RECORD.md`
  for why.

## TESTFILTER
`make tests TESTFILTER=<regex>` passes `-R <regex>` to `ctest`, which only runs tests whose name matches. We'll use
`make tests TESTFILTER=Sqe` later to run only our own tests without rebuilding/re-running all 147 upstream ones.

## Why the first build is slow (normally)
The very first configure step fetches GoogleTest (and its dependencies abseil/re2) via CMake's `FetchContent`, which
needs network access once. After that, and after the first full compile populates `ccache`, rebuilds are much faster
because only changed translation units (and anything that includes a changed header) get recompiled.
