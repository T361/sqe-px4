## What we did

  (NuttX, MAVLink definitions, microDDS, etc.) that the build needs.
- Verified the clone lands on the exact commit the assignment requires: `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`.

## Tag vs. commit hash — why they differ
`git rev-parse v1.17.0` printed `a5eb12d2ab591251faa009f76b2685b8cc64405d`. That is the **tag object**, not the commit —
annotated tags (the kind with a message/signature) are their own git object that *points at* a commit. The thing we actually
build is the commit it points to, which `git rev-parse 'v1.17.0^{commit}'` (or just checking out the tag) resolves to:
`d6f12ad1c4f70ad3230afd7d86e971421e02fef4`. If a report cites the tag object hash as "the commit we tested," that's wrong —
always cite the `^{commit}` value.

## Why `--recursive`
PX4 pulls several external projects in as git submodules rather than vendoring their code. Without `--recursive` those
directories stay empty and the build fails on missing headers. `git submodule status --recursive | grep -c '^-'` counts
submodules that are *not* checked out (a leading `-` means uninitialised) — we confirmed 0, i.e. all initialised.

## Toolchain install — resolved without sudo
PX4's own install script (`Tools/setup/ubuntu.sh`) installs cmake, ninja, lcov/genhtml, and build deps via `apt-get`,
which needs `sudo`. This environment has no passwordless sudo, so running that script wasn't possible non-interactively.
Instead, every missing tool was installed into the user's own home directory, which needs no elevated privileges at all:
- `cmake` and `ninja` — installed via `pip install --user cmake ninja` (both ship as pip-installable binary wheels).
- `lcov`/`genhtml` v2.0 — built from the upstream `lcov` project source and installed with
  `make install PREFIX=~/.local` (pure Perl scripts; no compilation needed).
- `DateTime.pm`, the one Perl module `lcov`/`genhtml` needed that wasn't already on the system — installed via
  `local::lib` (bootstrapped into `~/perl5` with no admin rights) and `cpan`, so it never touches the system Perl.
- `gcc`/`g++`/`gcov` (13.3.0), `python3` (3.12.3) and all of PX4's Python package requirements were already present
  on this machine system-wide, so nothing further was needed there.
`~/.bashrc` was updated to put `~/.local/bin` on `PATH` and load `local::lib` automatically in new shells, so this is
reproducible without repeating the install. Full tool-version evidence: `evidence/env/environment.md`. This whole
workaround (what was installed, how, and why instead of the sudo script) is logged in `work/DECISIONS.md` D-002.
