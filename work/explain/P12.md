# P12 explain-back — Testing workbook

## What we did
Generated `deliverables/24i3015_24i3166_24i3158_B.xlsx` from three existing sources of truth — never typed by
hand — using `tools/sqe_workbook.py`:
- `work/inventory/test_inventory.csv` → Sheet 1 "Test Inventory" (one row per student-authored test, including the
  disabled probes).
- `work/mcdc/mcdc_matrix.csv` → Sheet 2 "MC-DC Evidence" (one row per target MC/DC evaluation).
- `evidence/tests/xml/*.xml` + `evidence/tests/probes/*.xml` → the "Execution Result" column on Sheet 1, filled
  automatically from the real GTest XML output, not typed.

Validation: 116 inventory rows, 29 MC/DC rows, 113 PASS (the other 3 are the DISABLED probes, correctly shown as
NOT EXECUTED). Exactly 2 sheets, matching SPEC_05's schema column-for-column.

## Two real bugs found and fixed before the workbook could build cleanly
Before running the workbook generator, we ran the required traceability check (`tools/sqe_trace_check.py`) and it
failed with 4 errors — these were real problems, not something to route around:

1. **A CSV quoting bug.** Two inventory rows (the SQE-PRB-01/02 probe rows) had a `controlled_input` field like
   `put(t,{NaN,NaN,NaN},0,1) x10` written *without* quotes. Since that text contains commas, a real CSV parser (the
   same kind Excel/the workbook script uses) splits it into multiple columns instead of treating it as one field —
   which shifts every column after it out of position. The text still *looked* fine when read as plain text, which
   is exactly why it slipped through earlier phases; only parsing it properly as CSV exposed that `gtest_name` was
   resolving to the literal string `'0'` instead of the real test name. Fixed by quoting those two fields.
2. **A checker tool bug, not a documentation gap.** The traceability checker also reported 33 "missing comment
   block" warnings. We checked several by hand and found the comment blocks genuinely exist, with full Given/When/Then
   explanations — they were just longer than the checker expected (up to 19 lines for some of the more intricate
   MC/DC scenarios) while the script only looked 6 lines back from each test. Widened the lookback to 30 lines and
   re-ran: zero warnings, zero errors.

Both fixes are logged in `work/DECISIONS.md` (D-010) with the reasoning for why each was judged a real bug rather
than something to ignore or paper over.

## Why this order matters
Running the traceability + MC/DC checkers *before* generating the workbook isn't bureaucracy — the workbook script
itself validates against the same data and would have failed or (worse) silently produced a workbook with the wrong
test name for two probe rows if we'd skipped straight to generation. Catching it at the CSV level, with a clear
diagnosis of *why* it was wrong, is more useful for the viva than discovering a formatting glitch in the final
spreadsheet.
